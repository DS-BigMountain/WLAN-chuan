# 传：Web 端界面与交互逻辑

桌面应用采用已选定的第 1 版信息结构。标志及功能图标继续使用原有资源。两份 Web 方案分别适配桌面浏览器和手机浏览器；图标复用 src/assets/chuan.svg 及 src/web/index.html 中的 SVG 定义。

## 方案一：桌面浏览器工作台

设备侧栏保持可见，主工作区依次展示目标设备、发送区、接收审批和本次传输。目标设备名称与 IP 同时显示。浏览器自身身份与服务主机身份分别标注，避免将 Web 服务主机误认为当前浏览器。

选择文件或文件夹后，将当时选中的目标绑定到新任务。切换设备仅影响后续任务，已有任务继续使用原目标。Ping 与 IP 备注作用于当前选中设备；IP 备注保持当前会话范围。

发送到服务主机时，采用直接上传路径；发送到其他设备时，界面标明“浏览器 → 服务主机 → 目标设备”。上传至服务主机与目标设备接收分别展示状态，不能将上传进度达到 100% 表述为最终送达。

接收审批显示来源设备、顶层项目、实际文件数量和总大小。文件夹保持整体选择。在当前局域网 HTTP 场景中，目录写入不可用，文件夹选择与全部接受按钮不可用；用户仍可选择并接收单文件。

## 方案二：手机浏览器分视图

采用“发送／接收／状态”三个视图。发送视图保留目标设备卡片，通过底部设备选择面板切换目标。按钮采用适合触摸的尺寸。待确认接收请求与本次任务数量分别显示在对应视图标签上。

发送视图以选择文件为主操作。文件夹发送取决于系统文件选择器是否能够返回完整目录层级；当前手机示例采用不支持目录选择的环境，并提示先压缩后发送。该限制与文件夹接收所需的目录写入能力分别判断。

接收视图展示来源设备与项目列表。选择并接受单文件后，切换至状态视图，由用户发起下载。文件夹不可接收时，保持明确的不可用原因，允许用户仅接受同一批次中的单文件。

## 传输状态语义

| 状态 | 显示与行为 |
| --- | --- |
| 等待接收方确认 | 请求已提交；目标设备尚未接受 |
| 上传至服务主机 | 浏览器上传阶段，可显示上传进度 |
| 发送至目标设备 | 主机转发阶段，等待目标设备完成接收 |
| 已送达目标设备 | 目标设备完成相应接收流程 |
| 可下载 | 当前浏览器被授权获取该单文件 |
| 已交给浏览器 | 下载请求已交由浏览器处理，用户核对下载列表；不宣称已经写入本地磁盘 |
| 连接中断 | 禁用新的发送、下载及接收确认；保留任务和选择，重连后继续同步 |
| 已取消 | 取消相应任务，保留结果状态供用户检查 |

## 浏览器能力与审批

| 能力 | 处理逻辑 |
| --- | --- |
| 单文件发送 | 在线且选择目标后启用 |
| 文件夹发送 | 文件选择器支持目录层级时启用，选择结果缺少相对路径时说明原因 |
| 单文件接收 | 接受相应项目后提供下载入口 |
| 文件夹接收 | 浏览器具有目录写入能力并满足安全上下文条件时，先取得用户选择的目录，再提交接受决定 |
| 目录选择取消 | 保留待确认请求及用户选择，不提交接受决定 |
| 混合批次且文件夹不可接收 | 允许选择单文件；文件夹仍按整体处理，不能选其中某个子文件 |
| 传输上限 | 本浏览器、服务主机和接收方的有效限制共同约束批次；0 表示该层不设置主动上限 |
