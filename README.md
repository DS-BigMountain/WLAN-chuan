# 传（Chuan）

一款面向 Windows 与 Android 的轻量级局域网文件传输工具。

**传（Chuan）** 用于在同一局域网内的设备之间快速传输文件与文件夹，提供 Windows 桌面客户端、Android 应用以及内置 Web 访问能力。程序无需部署独立服务器，也不依赖 Node.js、Python 等运行环境，可通过局域网自动发现设备或手动指定 IP 地址建立连接。

当前版本：**V2.1**

## 功能特性

- **局域网设备自动发现**
  - 自动发现同一 IPv4 局域网内运行 Chuan 的设备
  - 支持设备在线状态检测
  - 设备名称旁显示 Win 客户端、Android 客户端、手机 Web 或电脑 Web 类型标签
  - 支持通过 IPv4 地址和端口手动连接
- **文件与文件夹传输**
  - 支持单文件及多文件批量发送
  - 文件夹默认按原始目录结构逐文件复制，包含空目录
  - 元数据检查、内容核验与数据传输分别调度：最多同时检查 15 个文件、核验 15 个文件、传输 4 个文件；已就绪文件立即进入传输队列，待传队列最多保留 32 项，自动重试使用独立通道
  - 相同相对路径的文件按大小和 SHA-256 核对；内容相同则跳过，缺失文件继续传输
  - 传输正文开始前登记完整目录清单，显示固定的总项目数与总大小
  - 设置中的“发送文件夹时打包为 ZIP”默认关闭；开启后生成不压缩的 ZIP64，接收端保存 ZIP 文件
  - 文件夹 ZIP 边打包边传输，CRC 与传输摘要随数据流计算；源文件不可读时停止并显示具体路径
  - 支持暂停与继续；暂停和连接中断均保留未完成数据，重新选择同一文件后可继续接收，原生接收端重启后仍可复用接收目录中的续传数据
  - 续传通过发送方、目标路径和长度定位候选数据，再核验全部已接收前缀的 SHA-256；文件内容不一致时重新接收，避免错误拼接。首次传输不进行全文件预读，续传核验需要读取已接收部分
  - Windows 接收临时文件禁用继承的 NTFS 压缩，空间检查按剩余待接收大小计算；清理已结束记录不会自动删除续传数据
  - 支持 Unicode 文件名
  - 目录复制遇到同名异内容文件时报告冲突并保留原文件，继续处理其他文件；普通单文件及 ZIP 使用编号避免覆盖
- **批次传输与接收审批**
  - 一次选择的多个项目以批次形式提交
  - 接收申请按发送人分组展开，文件右侧提供复选框，新申请默认勾选
  - “全选”可切换所有发送人的全部待接收项目；“接收”或“拒绝”仅处理已勾选项目
  - 同一批次中未勾选的项目保留待处理，可在已选项目传输后继续接收
  - 文件夹作为不可拆分的整体接受或拒绝
  - 发送端明确显示“等待对方确认”；连接保持正常时，请求持续保留至接受、拒绝或取消
  - 网页后台暂停心跳时保留待发送任务；页面恢复后继续，实际失败时同步停止打包
  - 失败文件进入独立重试通道，正常队列继续发送；自动重试连续 30 秒无进展时显示“传输失败超时”
  - 失败文件可单独重新加入发送队列；原生客户端重试保留原路径和有效批次授权，取消或拒绝后的再次发送重新申请接收
  - 支持自动接收模式
  - 可分别限制单批文件数量和单批数据大小
- **Windows 原生客户端**
  - 原生 Win32 桌面程序
  - 提供设备列表、传输任务、进度、速率及结果状态
  - 支持拖放发送
  - 支持快速打开文件所在目录
  - 支持取消任务及清理已结束任务
  - “清除已结束”保留活动批次及其中已完成的子项，不中断传输；进行中与已结束任务分别显示状态标识和背景
  - 分别提供文件与文件夹选择入口
  - 主窗口支持切换自动接收，以及按发送、接收方向筛选本次传输
- **Android 应用**
  - 独立提供设备发现、文件与文件夹互传、批次审批、进度与速率显示
  - 支持取消、删除、筛选记录，以及打开和分享接收文件
  - 使用系统文件选择器与持久目录授权，无需授予全盘文件访问权限
  - 服务开启时可独立接受电脑、手机和浏览器连接
  - 前台服务在应用进入后台后继续运行，通知栏提供停止入口
  - 可向局域网浏览器提供 Web 页面、Android APK 和 Windows 程序下载
- **内置 Web 服务**
  - 可通过手机、平板或其他电脑的浏览器访问
  - 无需额外部署 Web 服务
  - Web 资源直接嵌入可执行文件
  - 支持浏览器上传、下载、设备选择及 Ping
  - 不同浏览器实例拥有独立客户端身份
  - 浏览器身份、限制设置和任务归属按服务主机隔离
  - 服务主机身份或运行会话变化后停止旧请求，需显式重新连接
  - 桌面与手机浏览器使用同一传输主界面，包含发送区、接收申请和“本次传输”列表
  - 任务显示当前进度、速率及接收结果，可按全部、发送、接收筛选
  - 目标 Web 页面不支持目录写入时，发送端显示说明并提供“打包传输”按钮，本次发送使用 ZIP，不更改默认设置
  - 设备侧栏按窗口宽度调整，设备较多时可独立滚动
- **完整性校验**
  - 文件采用流式读写
  - Windows 与 Android 客户端协议使用 SHA-256 进行完整性验证
  - 网页普通文件直接上传；文件夹 ZIP 在打包时计算 SHA-256，接收端校验完整后保存
  - 完成相应检查并刷新文件缓冲区后才提交正式文件
  - 暂停或连接中断时保留可续传数据；恢复前核验已接收内容
- **传输诊断日志**
  - 默认记录文件阶段、耗时、队列等待、并发数量、吞吐、文件读写、校验、重试与错误；日志包含文件相对路径及必要的设备、网络信息，不记录文件正文或会话令牌
  - 使用异步批量写入，传输进度按秒采样；日志导出文件会标明记录丢弃、存储错误及容量截断情况
  - Windows：设置 → 导出诊断日志，程序打开导出文件所在目录
  - Android：设置 → 导出诊断日志 → 选择保存位置
  - Web：设置 → 导出诊断日志，下载页面记录及当前会话对应的主机记录；页面记录使用浏览器本地存储保留
  - 诊断一次完整传输时，发送端与接收端均使用本版本；传输结束后分别导出日志，保留原始 JSONL 文件供分析
- **Ping 与设备反馈**
  - 支持向指定设备发送 Ping
  - 桌面端、Android 应用和 Web 端均提供可视化反馈
  - 可用于快速确认设备是否处于可交互状态

## 系统要求

### 运行环境

- Windows 10 x64
- Windows 11 x64
- Android 8.0 或更高版本，系统提供已更新的 Android System WebView
- IPv4 局域网环境

Windows 端为独立可执行文件。Android 端为 APK，开启服务后使用通知栏可见的前台服务。

### 开发环境

从源码构建需要：

- Visual Studio C++ 桌面开发工具
- Windows SDK
- CMake 3.24 或更高版本
- 支持 C++20 的 MSVC 工具链
- Python（运行部分集成测试时需要）
- Node.js（运行 Web 测试时需要）

完成 Release 构建后，可从普通用户 PowerShell 生成交付包：

```powershell
cmake -S . -B .\build\v2.1 -A x64
cmake --build .\build\v2.1 --config Release --target Chuan
.\tools\package.ps1 -BuildDirectory ".\build\v2.1"
```

打包脚本沿用项目当前版本，默认在 `__release_packages__\临时\时间\` 中创建交付目录；指定 `-VersionedRelease` 时，文件直接写入 `__release_packages__\<版本号>\`，目标目录已存在时停止打包。脚本验证可执行文件内容、签名状态及 ZIP 内容。脚本将本次交付目录和可执行文件设置为中完整性级别，避免继承构建目录的低完整性标签。

## 快速开始

### 1. 启动程序

在需要进行文件传输的 Windows 设备上运行：

```
Chuan.exe
```

程序启动后会自动广播设备信息，并持续检测局域网内其他在线设备。

### 2. 选择目标设备

在设备列表中选择需要发送文件的目标设备。

如果网络环境限制了 UDP 广播，可以使用“手动连接”功能输入目标设备的：

```
IPv4 地址
TCP 端口
```

建立直接连接。

### 3. 发送文件

选择目标设备后，可以：

- 将文件拖入发送区域；
- 选择一个或多个文件；
- 选择文件夹。

对于批量发送任务，接收端会收到完整项目清单，并根据接收设置决定是否接受。

在 Windows 客户端、Web 页面或 Android 应用中，点击文件夹任务名称，可直接在原任务项下方展开目录。各级目录和文件显示名称、大小及逐项结果，正在传输的文件显示进度和速率，失败文件显示具体原因。

文件夹默认逐文件复制到接收目录中同名的子目录。接收端核对已有文件，内容相同则跳过；内容不同则报告冲突并保留原文件，同时继续处理其他文件。取消或断网后，已提交文件保留。重新选择同一文件夹并发送到同一接收位置，程序重新核对实际目录，只传输缺失文件。该行为不依赖历史任务记录，重启程序后仍然适用。

Windows、Android 和 Web 的发送设置均提供“发送文件夹时打包为 ZIP”，默认关闭，各端独立保存，主机客户端开关不改变 Web 页面设置。开启后，文件夹作为单个 ZIP 流式传输，不执行目录逐文件补传。

发送端在审批期间显示“等待对方确认”。连接正常时，申请持续保留，直至接收方接受、拒绝或发送方取消。被拒绝、取消或因网络问题失败的发送记录提供“重试”入口；重试会使用原目标设备重新发起审批，文件夹重新核对完整目录并补传缺失文件。浏览器页面仍持有原文件时可直接重试；页面刷新后若原文件已释放，需要重新选择文件。

### 4. 接收文件

默认情况下程序启用自动接收。

默认保存位置：

```
%USERPROFILE%\Downloads\传
```

关闭自动接收后，接收端需要手动确认传输请求。Windows 主界面的接收申请列表显示待处理数量，可选择任一申请接受、接受部分项目或拒绝；尚未处理的申请不阻止后续申请显示。

对于包含多个项目的批次，可以：

- 全部接受；
- 仅接受指定项目；
- 拒绝整个批次。

目录复制不会覆盖同名异内容文件。普通单文件及 ZIP 传输遇到同名文件时，程序自动添加编号。

点击主窗口底部的“接收目录”可查看当前路径、打开目录或修改保存位置。可通过“选择目录”指定文件夹，也可直接编辑绝对路径，点击“保存”后生效。

## Web 访问

Windows 客户端与 Android 应用均可独立提供局域网 Web 服务。

在桌面程序中打开“Web 服务”后，会显示类似以下地址：

```
http://192.168.1.10:45871/
```

在与服务主机处于同一局域网的设备上，通过浏览器访问该地址即可使用 Web 客户端。

Web 客户端支持：

- 查看在线设备
- 选择目标设备
- 上传文件
- 上传文件夹（取决于浏览器能力）
- 接收文件
- Ping 设备
- 查看传输状态
- 设置临时设备备注
- 设置批次传输限制

无需安装额外 Web 服务，也不依赖外部网站。

### 浏览器文件夹支持

浏览器发送和接收文件夹的能力取决于浏览器及操作系统提供的文件系统接口。Android 应用通过系统目录授权接口选择文件夹；手机网页由浏览器调用文件选择器，具体界面及目录支持取决于浏览器和系统文件管理器，网页无法直接指定原生应用的授权界面。

部分移动端浏览器或 Android WebView 宿主可能无法正确提供目录选择能力。

如果浏览器不支持文件夹选择，可先将目录压缩为普通压缩文件后发送。

浏览器默认逐文件发送目录。支持目录句柄接口的浏览器能够枚举空目录；传统目录文件选择器只能提供文件及其父路径，无法识别独立空目录。开启 ZIP 设置后，目录边打包为不压缩的 ZIP64 边上传；目标为其他原生客户端时，主机同步转发数据，无需先保存完整归档。发送过程中需要保持页面开启和源文件可读。

浏览器直接接收目录需要安全上下文及目录写入接口。用户选择目标目录后，程序按相对路径核对已有文件，仅下载缺失文件，并在完整性校验和写入提交后确认完成。普通局域网 HTTP 页面通常不具备该接口，可使用原生客户端接收目录，或发送 ZIP 并通过浏览器下载。

每个顶层项目均可单独接受或拒绝。目录接收在审批时选择保存位置；普通文件及 ZIP 通过“下载”保存，保存结果需在浏览器下载列表中核对。

发送到其他设备时，上传进度仅表示浏览器向服务主机发送数据的进度。程序继续显示主机转发状态，直到目标设备完成相应接收流程。手机端切换目标设备仅影响后续发送，已提交任务保持原目标。

## Android 使用方法

Android 应用源码位于项目根目录的 `mobile/` 文件夹，当前版本为 **2.1**。

### 安装与桌面下载入口

交付目录同时提供 `Chuan.exe`、`Chuan-2.1-android.apk` 和 Windows 便携 ZIP。ZIP 内包含同一 APK；桌面程序与 APK 保持在同一目录时，桌面端通过底部“Web 服务”打开网页，网页中的“Android 客户端”可直接下载安装包。

手机连接相同局域网后访问该地址，下载 APK 并按照 Android 安装器的提示完成安装。Android 应用自身也提供当前安装 APK 的下载入口。

### 文件传输与目录授权

打开应用后服务自动开启。在主界面切换目标设备，选择文件或文件夹；从其他应用的系统分享菜单选择“传”，可将分享的文件发送至指定设备。

主界面顶部可切换自动接收，接收申请在发送区下方按发送人分组展开，新到项目默认勾选。“全选”切换全部待处理项目，“接收”和“拒绝”仅处理勾选项；未勾选项目保留待处理，可稍后继续接收。文件夹作为整体处理。“本次传输”列表按全部、发送、接收筛选，显示进度、速率与结果，并提供取消、重试、删除、打开及分享操作。删除接收记录会同时删除本次实际接收的文件，保留目录结构及因内容相同而跳过的已有文件；“清除已结束”仅隐藏记录。

默认接收位置为应用专属目录 `Android/data/local.chuan.app/files/Download/传`。可通过主界面底部“接收目录 → 修改”选择系统目录，应用保存系统授予的持久读写权限；权限失效时，接收任务报告具体保存错误，可重新选择目录。点击接收目录旁的“查看”可浏览、打开和分享已有文件，服务重启或清除任务记录后仍可使用。卸载应用会清除应用专属目录中的文件，需长期保留的资料可使用已授权的系统目录。

### 手机作为服务主机

服务开启时，应用通过前台服务保持局域网监听、设备发现和 Web 中转。界面进入后台后，服务继续工作；主界面底部“Web 服务”和通知栏均提供停止入口。停止服务会终止尚未完成的传输。

在应用内复制 Web 地址，其他设备的浏览器即可连接手机。默认端口与桌面端一致。服务运行期间保持 CPU 唤醒和组播接收，持续运行时会消耗电量；系统强行停止应用后，需要重新打开应用才能恢复服务。

### Android 构建

构建环境需要 JDK 17 或更高版本、Android SDK Platform 35 和 Build Tools 35.0.0。应用不依赖 Gradle、AndroidX 或 NDK，生成的 APK 可在不同 CPU 架构的 Android 设备上运行。

先构建同版本桌面程序，再执行：

```powershell
.\mobile\build.ps1 -AndroidSdk "C:\Android\Sdk"
.\tools\package.ps1 -BuildDirectory ".\build\v2.1" -AndroidApk ".\mobile\build\outputs\Chuan-2.1-android.apk" -AndroidSdk "C:\Android\Sdk"
```

`-DesktopExe` 使用相对路径时相对于 `mobile/`，因此也可省略该参数以采用默认桌面构建路径。APK 使用 `mobile/.signing/` 中的持久发布密钥；密钥和密码文件不进入源码仓库或交付目录，构建环境需妥善保留它们。

## 多服务主机会话

同一局域网可以同时运行多个 Windows 和 Android 服务主机。每个主机具有独立设备 ID，每次服务启动生成新的运行会话标识。浏览器使用当前主机下的身份、设置与请求令牌，跨主机浏览器设备通过所属主机路由，不以显示名称或 IP 作为任务身份。

同一浏览器可同时打开多个主机页面。页面中的发送、审批、取消和下载请求均携带主机及运行会话信息；地址被另一台设备占用或服务重启后，旧页面停止活动任务并显示“重新连接”。重新连接后，可重新选择目标并提交传输。

## 网络说明

Chuan 默认使用以下端口：

| 类型 | 默认端口 | 用途                          |
| ---- | -------- | ----------------------------- |
| TCP  | `45871`  | 文件传输、设备通信及 Web 服务 |
| UDP  | `45872`  | 局域网设备发现                |

Windows 防火墙需要允许程序进行相应的局域网通信。

如果 UDP 广播不可用，可以通过“手动连接”直接连接对方 IPv4 地址。

### 网络范围

Chuan 主要面向：

```
可信 IPv4 局域网
```

当前版本不提供：

- NAT 穿透
- 公网中继服务
- 云端设备发现
- 互联网远程传输

## 传输机制

文件采用流式方式读取和写入。目录复制先检查目标路径：缺失文件直接传输，不进行整文件预读；存在同名文件时，先检查类型与大小，再按 SHA-256 判断是否可以跳过，不将名称或修改时间作为内容相同的依据。原生传输与网页目录接收在传输过程中计算和验证 SHA-256，接收文件先写入临时文件，完成后再提交。已复制目录的重复发送需要读取源文件及目标已有文件以核对内容。

Windows 与 Android 的普通文件传输同样执行 SHA-256 校验。网页普通单文件上传沿用服务主机提供的校验能力；不执行摘要校验时，长度及 TCP 检查不等同于端到端哈希验证。

典型流程如下：

```
发送请求
    ↓
接收端审批
    ↓
开始传输
    ↓
写入临时数据
    ↓
长度及写入结果检查（Windows 与 Android 客户端协议另执行 SHA-256 比对）
    ↓
提交正式文件
```

暂停或连接中断时，原生接收端保留可续传的临时数据。再次发送同一文件时，程序核验已接收前缀，核验通过后从断点继续；不匹配的数据不用于拼接。

目录支持文件级补传：已完成且内容相同的文件跳过，未完成的单个文件从头传输。当前不支持单个大文件内部按字节位置续传。

## 批次限制

桌面客户端、Android 应用和 Web 客户端均支持配置：

- 单批最大文件数量
- 单批最大总大小

默认值均为：

```
0
```

表示不设置业务层面的主动限制。

实际可传输规模仍然受到以下因素约束：

- 可用磁盘空间
- 可用系统内存
- 网络状况
- 文件系统限制
- 协议整数范围

## Web 中转

浏览器向其他设备发送文件时，文件会首先上传至当前 Web 服务主机的私有暂存目录，再由服务主机转发给最终接收设备。

流程如下：

```
浏览器
   ↓
Web 服务主机
   ↓
目标设备
```

最终目标设备仍然按照自己的接收策略决定是否接受文件。

暂存数据会在任务结束后一段时间自动清理，程序正常退出时也会执行清理。

## 安全说明

Chuan 的设计目标是方便可信局域网内部的设备之间快速传输文件，而不是作为互联网文件传输协议使用。

### 当前安全边界

文件传输使用普通 TCP 连接。

当前版本：

- **不提供传输层加密**
- **不提供用户账号认证**
- **不提供公网安全接入能力**

Web 客户端使用随机身份和请求令牌进行会话归属与部分跨站请求限制，但这些机制不能替代正式的身份认证或加密协议。

因此，请仅在可信局域网环境中使用 Chuan。

对于公共 Wi-Fi、酒店网络、校园公共网络或其他不可信网络环境，应谨慎启用文件接收及 Web 服务。

## 启动故障处理

### 接收目录或配置文件不可写

程序默认使用 `%LOCALAPPDATA%\Chuan\settings.ini`，配置位置与可执行文件所在目录无关。该文件记录的接收目录失效，或配置文件的写入权限发生变化，均可能影响启动。

程序启动时检查接收目录的写入能力。原目录不可用时，程序尝试使用 `%LOCALAPPDATA%\Chuan\received`，并在启动提示中列出原路径、系统错误及替代路径。使用 `--data-dir` 时，备用目录为该配置目录下的 `received`。原目录及其中的文件保持原状。

默认用户配置目录下的备用目录也不可写时，程序继续尝试可执行文件旁的 `data\received`，并将配置保存到 `data\settings.ini`。仅配置目录不可写时，程序尝试将配置保存到该便携目录，同时保留仍然可写的接收目录。显式指定 `--data-dir` 时不启用此回退。

便携配置中位于配置目录内部的接收路径按当前配置目录解析；位于配置目录之外的自定义路径保留其绝对位置。使用便携模式时，应同时保留程序旁的 `data` 目录。

程序区分显式便携配置与自动回退配置。显式便携配置优先读取；受限进程或用户配置目录不可写时，继续使用自动回退配置；普通用户进程且用户配置目录可写时，恢复读取用户配置目录。

需要使用独立配置时，可在程序所在的可写目录中打开 PowerShell，执行以下命令初始化配置及接收目录：

```powershell
.\Chuan.exe --data-dir ".\data" --receive-dir ".\data\received"
```

后续使用 `.\Chuan.exe --data-dir ".\data"` 启动，即可保留在界面中修改的接收目录。

配置保存失败时，程序显示具体路径和系统错误，并继续本次会话；部分设置可能无法在重启后保留。应检查 `settings.ini` 的只读属性、文件占用和用户写入权限。所有接收目录均不可写时，程序终止启动，并提供各失败路径。也可通过 `--receive-dir "D:\接收文件"` 指定可写目录，通过 `--data-dir "D:\Chuan配置"` 指定配置目录。

### 受限启动环境

从沙箱或其他受限进程启动时，程序可能继承受限访问令牌。可执行文件带有低完整性标签时，程序也可能以低完整性级别运行。Windows 的完整性控制会限制此类进程向普通用户目录写入；目录对当前账户具有写入权限，并不能消除这一限制。

目录访问返回错误 5 时，程序检查访问令牌及进程完整性级别，并在启动提示中说明检测到的限制；传输诊断日志同时记录完整性级别、令牌状态及实际配置目录、接收目录。

常规桌面使用可从文件资源管理器直接打开 `Chuan.exe`。需要在受限环境内运行时，应通过 `--data-dir` 和 `--receive-dir` 指定该环境允许写入的目录。

### Windows SmartScreen 提示

当前发行包未附加发行者数字签名，Windows SmartScreen 可能显示“Windows 已保护你的电脑”及“发布者未知”。该提示属于 Windows 的应用信任检查，与程序内部的目录访问错误分别发生。

对于已确认来自本项目可信构建的程序，可在该文件的 SmartScreen 提示中选择“更多信息”后选择“仍要运行”；截图已展开详细信息时，可直接选择“仍要运行”。无需关闭系统级 SmartScreen 或 Microsoft Defender。来源不明的副本应先重新获取可信构建。

面向外部分发时，需要使用受 Windows 信任的代码签名证书对最终可执行文件执行 Authenticode 签名并添加时间戳。有效签名用于验证发行者身份，但 SmartScreen 仍可能根据文件信誉或设备策略显示提示。修改版本资源或使用未受信任的自签名证书不能替代发行签名。

## 当前限制

当前存在以下设计限制：

- 原生客户端支持 Windows 10 / Windows 11 x64 与 Android 8.0 及以上系统
- 仅支持 IPv4 局域网环境
- 不提供公网穿透
- 不提供端到端加密
- 不提供账号认证
- 原生客户端续传数据绑定发送方身份、相对路径与长度；恢复前核验已接收内容，源文件发生变化时重新接收
- 浏览器普通下载由下载管理器控制暂停与继续；目录接收的断点记录限同一浏览器来源使用，恢复时需重新授权目标目录
- 浏览器目录写入接口采用临时提交机制，续传时可能额外占用与已有文件相当的磁盘空间
- 传统浏览器目录选择器无法提供独立空目录
- 浏览器文件夹功能受浏览器和系统能力限制
- 普通浏览器下载无法确认最终磁盘写入；支持目录写入接口时以提交结果确认
- 部分 Android WebView 浏览器可能无法正确支持文件夹选择
- Windows 可执行文件未附加 Authenticode 发行者签名；Android APK 使用项目持久发布密钥签名

## 使用场景

Chuan 适用于需要在可信局域网中快速交换文件的场景，例如：

- Windows 电脑之间传输文件
- Android 手机与 Windows 电脑双向传输文件及文件夹
- Android 手机独立提供局域网文件接收与 Web 中转服务
- 无需登录账号的临时文件共享
- 无互联网环境下的局域网数据交换
- 开发、测试及实验室内部文件传输
